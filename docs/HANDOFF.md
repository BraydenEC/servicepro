## 🚨 Priorities that must not slip

1. **Deploy at Phase 4, not at the end.** "No live deployment = max 5/10." The first deploy happens as soon as the mock UI looks presentable, *before* Supabase. This secures the grade floor early instead of betting it on the last hour.
2. **The live URL must ultimately render real Supabase rows.** The mock fallback is deliberately good enough to hide an empty database — which is a grading liability, because "Supabase evidence" is scored separately. Mock is the safety net, never the deliverable.
3. **Documentation outscores the app: 4.5 points vs 2.0.** Phase 9 is not a formality.
4. **Evidence accrues during the work, not after.** Screenshots at each phase, `PROMPT_LOG.md` updated as prompts happen. Reconstructing this at the end is where marks get lost.
